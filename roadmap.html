Recommendation: Migrate to Supabase (ditch Firestore)
PostgreSQL is far better for music app data. You can do JOIN songs ON playlists.song_ids, run aggregated play-count queries, and structure relational listen_events natively. Firestore's document model gets painful fast with filtering and sorting across collections. Use supabase_flutter + supabase_auth_ui — auth, storage, and realtime all included. Your existing SongModel.fromMap() just needs the field names updated.

ML Recommendations
Collaborative filtering → "Discover Weekly" auto-playlist
High Priority listen_events required!
▼
⚠️ This only works if you've been logging listen_events since Phase 1. Don't skip that step!
Start simple — Collaborative Filter (SQL)
-- "Users who liked what you liked also liked..." SELECT s.*, COUNT(*) as overlap_score FROM liked_songs ls1 JOIN liked_songs ls2 ON ls1.uid != ls2.uid AND ls1.song_id = ls2.song_id -- shared taste JOIN liked_songs ls3 ON ls3.uid = ls2.uid AND ls3.song_id NOT IN ( SELECT song_id FROM liked_songs WHERE uid = $current_user ) JOIN songs s ON s.id = ls3.song_id WHERE ls1.uid = $current_user GROUP BY s.id ORDER BY overlap_score DESC LIMIT 20;
Scaling up later
  • Run the query as a Supabase Edge Function on a daily cron, cache results in a recommendations table
  • When you have 10k+ events, export to Python, use implicit library for ALS matrix factorization
  • "Discover Weekly" playlist: auto-generated every Monday, shown on Home screen
